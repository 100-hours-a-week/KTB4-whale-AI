# attention score

## 배경

- 언어 모델은 시퀀스 길이 수천 토큰, 학습 데이터 수조 토큰 단위를 다룹니다. 이 규모에서 6단계에서 진행했던 직렬 계산(순차 계산)이 강제된다는 것은 "가능한 시간 안에 끝내야 한다"는 모델이 실용적이지 못하다는 것을 의미합니다. 수년이 걸리면 의미가 없기 때문입니다. 그래서 GPU의 수천 개 코어를 동시에 활용하는 병렬 계산이 필요해졌습니다.
- 6단계 RNN Cell에서는 구조상 `h_{t-1}`이 계산되기 전에는 `h_t`를 계산할 방법이 수학적으로 없습니다. 이 데이터 의존성(data dependency) 때문에, GPU 코어가 아무리 많아도 시간 축(time step)만큼은 순차적으로 계산할 수밖에 없습니다. 시간 복잡도 측면에서 시퀀스 길이 `T`에 비례해서 `O(T)`만큼 늘어나고, 코어 수를 늘려도 이 관계는 줄어들지 않습니다. (여기에 vanishing gradient(기울기 소실)까지 더해지면, RNN 구조로는 실제 서비스 규모의 데이터를 감당 가능한 시간 안에 학습시키는 것 자체가 현실적으로 불가능합니다.)
- 7단계는 이 문제를 "위치 간 관계도를 이전 위치의 계산 결과 없이 즉시 계산하는" 병렬 계산 방식으로 해결합니다. `Q = X @ Wq`, `K = X @ Wk`, `S = Q @ K.T`는 각 위치의 원본 입력(`X`)만으로 계산되므로, 다른 위치의 계산이 끝나기를 기다릴 필요가 없습니다. 이 데이터 의존성의 제거가 GPU 병렬 계산을 가능하게 만드는 근거입니다.

## 동작 원리

- "직렬을 병렬로 바꾼다"는 목표만 보면, Q, K의 필요성을 보기 어렵습니다. 하지만 이 목표를 구체적으로 풀어보면 왜 Q, K가 필요한지 드러납니다.
- RNN의 하던 "위치 t가 이전 위치(0부터 t-1)의 정보를 참조해서 자신의 표현을 만든다"는 일을 순차 계산 없이 진행하려면, "순서대로 하나씩 거치지 않고, 위치 i가 위치 j의 정보를 얼마나 참조해야 하는지 어떻게 즉시 알아낼까"는 질문에 답할 방법이 있어야 합니다.
- "위치 i가 위치 j를 얼마나 참조해야 하는지"를 숫자 하나로 표현하려면, 두 벡터(위치 i, 위치 j의 표현) 사이의 관련도(relatedness)를 계산하는 방법이 필요합니다. 이 관련도를 계산하는 손 쉬운 방법이 벡터의 내적곱(dot product)를 사용하는 방법입니다. 두 벡터의 방향이 비슷할수록 내적값이 커지는 성질을 이용합니다. (언어의 관련성을 나타내기 위한 병렬 계산 방법)
- 이 때, 그대로 내적하면 대칭성(i가 j를 참조하는 정도와 j가 i를 참조하는 정도가 같다는 성질)이 생기기 때문에 비대칭성(참조의 필요성이 서로 다를 수 있다는 성질)을 표현해야 합니다. 이를 위해 같은 X라도 Q, K를 사용해 질문하는 쪽과 대답하는 쪽을 갈라놓도록 설계합니다.

**forward**

```python
# Before — 6단계(rnn_cell.py)
def step(self, x_t: NumpyValue, h_prev: NumpyValue) -> tuple:
    h_t = (x_t @ self.Wxh + h_prev @ self.Whh + self.bh).sigmoid()
    y_t = (h_t @ self.Why + self.by).sigmoid()
    return y_t, h_t

def forward(self, sequence: list) -> list:
    batch_size = sequence[0].shape[0]
    h = self.init_hidden(batch_size)
    outputs = []
    for x_t in sequence:
        x_val = NumpyValue(x_t)
        y_t, h = self.step(x_val, h)
        outputs.append(y_t)
    return outputs

# After — 7단계(attention_score.py)
def forward(self, X: np.ndarray) -> NumpyValue:
    X_val = NumpyValue(X)
    Q = X_val @ self.Wq
    K = X_val @ self.Wk
    S = Q @ K.transpose()
    return S
```

- 6단계는 `sequence`를 시점별로 순회하는 `for` 반복문과, 이전 시점의 `h`를 다음 계산에 전달하는 `step()` 호출이 반드시 필요했습니다.
- 7단계는 시퀀스 전체(`X`, 모양 `(seq_len, d_model)`)를 한 번에 받아서, 반복문 없이 `Q @ K.transpose()` 한 번으로 모든 위치 쌍의 유사도를 계산합니다. `step()`에 대응하는 개념 자체가 없습니다.
- `Q = X @ Wq`(query, 각 위치가 "무엇을 찾고 있는지"), `K = X @ Wk`(key, 각 위치가 "무엇을 제공하는지")는 6단계의 `Wxh`(입력을 hidden으로 변환)와 같은 역할의 선형 변환이지만, `Wxh`가 매 시점 재사용되며 시간 축을 연결했던 것과 달리, `Wq`, `Wk`는 시퀀스 전체에 한 번만 적용됩니다.
- forward 실행 시, NumpyValue 동작 과정
  1. (`X_val @ self.Wq`) 곱셈 연산(`__matmul__`)이 실행되어 `Q`가 생성됩니다. 이 노드는 `X_val`, `self.Wq`를 자식(`_children`)으로 `self._prev`에 기록합니다.
  2. (`X_val @ self.Wk`) 1과 동일한 과정이 `K`에 대해 반복됩니다. `X_val`이 `Q`와 `K` 양쪽에 공유되는 자식이라는 점이 4단계에서 다룬 "다중 경로 gradient 합산"과 같은 구조입니다.
  3. (`K.transpose()`) 새로 추가된 연산입니다. `K.data.T`로 전치된 배열을 담은 새 노드가 생성되고, `_prev`에는 `K` 하나만 자식으로 기록됩니다.
  4. (`Q @ K.transpose()`) 곱셈 연산이 실행되어 `S`(모양 `(seq_len, seq_len)`)가 생성됩니다. `S[i, j]`는 `i`번째 위치의 query와 `j`번째 위치의 key를 내적한 값입니다.
  5. `S`를 반환합니다. 이 시점에서 `S`의 `_prev`를 따라가면 `Q`, `K`를 거쳐 `X_val`, `Wq`, `Wk`까지 3단계 만에 도달합니다 — 시퀀스 길이가 몇이든 이 깊이는 바뀌지 않습니다(검증 결과, 아래 결과 정리 참고).

## 결과 정리

**표 1. attention score 검증 결과**
| 검증 항목 | 결과 |
| --- | --- |
| `transpose()` backward | `sum(A.T) = sum(A)`이므로 모든 원소 gradient가 1.0으로 정확히 일치 |
| `S = Q @ K.T` backward vs 수치 미분 | `Wq` 6개 원소 전부 일치 |
| 시퀀스 길이 10에서 `S`를 만드는 계산 그래프 깊이 | 3 (시퀀스 길이와 무관하게 일정) |

## 결론 및 한계

- 6단계에서 확인한 두 문제 중 하나(병렬화 불가, 경로 길이가 시퀀스 길이에 비례)가 해결됐습니다. `S`를 만드는 계산 그래프 깊이가 시퀀스 길이 10에서도 3에 머물렀다는 게 실측으로 확인됐습니다(표 1). 이는 RNN이 `t=0`부터 `t=9`까지 정보를 전달하려면 9번의 순차 `step()`을 거쳐야 했던 것과 대비됩니다.
- 다만 무작위 초기화 상태의 `Wq`, `Wk`로 실제 유사도를 계산해보면, 동일한 토큰(`[1,0,0,0]`을 두 번 넣은 경우)과 다른 토큰(`[0,1,0,0]`) 사이의 점수 차이가 아직 의미 있는 패턴을 보이지 않았습니다. `Wq`, `Wk`가 아직 어떤 과제에 대해서도 학습되지 않았기 때문입니다. 지금 구현은 "유사도를 계산하는 구조"만 검증한 것이지, "의미 있는 유사도를 학습하는 것"까지 확인한 게 아닙니다.
- 더 근본적인 한계는, `S`(attention score)만으로는 실제 정보가 이동하지 않는다는 점입니다. `S[i,j]`는 `i`와 `j`가 얼마나 유사한지를 나타내는 숫자일 뿐, 그 유사도에 따라 실제 값(정보)을 섞어주는 단계가 없습니다. 이게 로드맵(`docs.md`)이 명시한 이번 단계의 한계인 "유사도 점수만으로는 실제 정보 전달이 안 된다"는 점입니다.
- 이 한계가 8단계(scaled dot-product attention)로 넘어가는 이유입니다. 8단계는 `V`(value, 각 위치가 실제로 전달할 정보)를 추가하고, `S`를 softmax로 정규화한 뒤 `V`에 가중합(weighted sum)으로 곱해서, "유사도에 비례해 실제 정보를 섞는" 단계를 완성합니다.
