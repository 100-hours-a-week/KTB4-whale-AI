# scaled dot-product attention

## 배경

- attention이 풀어야 할 근본 과제는 "각 위치가 다른 위치들의 정보를 참조해서, 문맥을 반영한 표현을 만드는 것"입니다. 예를 들어 "그것"이라는 대명사가 문장 안의 특정 명사를 가리킨다면, "그것"의 표현은 그 명사의 실제 의미(정보)를 반영해야 합니다.
- 7단계에서는 "그것"과 그 명사 사이의 관련도 점수만 계산했을 뿐, "그것"의 표현에 해당 명사의 실제 내용을 반영하는 단계가 없습니다. `S[i,j]`가 아무리 커도, 위치 `j`의 정보가 위치 `i`로 전혀 옮겨가지 않습니다. (`S`를 계산하고 나면 forward가 그냥 끝나버립니다.)
- 즉 7단계는 "누구를 참조해야 하는지 알아내는 것"까지는 해결했지만, "그 참조를 실제로 반영해서 표현을 바꾸는 것"은 아무런 장치가 없는 상태입니다. 이 장치가 없으면, 아무리 유사도를 정교하게 계산해도 모델의 출력 자체는 원본 입력(`X`)의 정보만 담고 있고, 문맥이 반영되지 않습니다. attention의 개념이 성립하려면 이 반영 단계가 반드시 있어야 합니다.
- 8단계는 이 문제를 `V`(value, 각 위치가 실제로 전달할 정보)를 추가하고 `S`를 softmax로 정규화한 뒤 `V`에 가중합(weighted sum)으로 곱해서 해결합니다. 이 가중합이 "위치 `j`의 정보를 관련도(`S[i,j]`)만큼 위치 `i`의 출력에 실제로 섞어 넣는" 단계입니다.

## 동작 원리

- 8단계의 목표는 "위치 `j`의 정보를 관련도(`S[i,j]`)만큼 위치 `i`의 출력에 실제로 섞어 넣는 것"입니다. 이 표현을 수학적으로 엄밀히 옮기면 가중 평균(weighted average)가 됩니다. 가중 평균이 성립하려면, 그 정의 자체가 다음 두 조건을 만족해야 합니다.

**표 1. 가중 평균의 수학적 정의가 강제하는 조건**
| 가중 평균의 정의 | 요구되는 조건 |
| --- | --- |
| "가중치는 각 항목이 차지하는 비중이다" | 가중치가 음수면 안 됨 (비중이 마이너스라는 건 정의 자체가 성립 안 함) |
| "가중치를 다 더하면 전체(100%)가 된다" | 가중치의 합이 정확히 1이어야 함 |

- "가중 평균"이라는 개념이 성립하기 위해 음수가 없고 합이 1인 조건을 만족하는 어떤 함수를 사용해도 원칙적으로는 무리가 없습니다. 예를 들어 S_scaled에서 최소값을 빼서 전부 양수로 만든 뒤 합으로 나누는 min-max 정규화 방법도 해당 조건을 만족합니다.
- **softmax는 필요조건**이 됩니다. softmax 방정식은 아래와 같습니다. softmax는 어떤 실수 벡터를 넣어도 "전부 양수이며, 합이 정확히 1이 되는" 벡터로 조정하는 함수입니다.

  $$
  softmax(x_i) = e^(x_i) / sum_j(e^(x_j))
  $$

- 대표적인 방법 두 가지 min-max 정규화, softmax 방식이 있는데, 그 중 softmax를 선택하는 이유는 "조건을 만족하는 방법 중 하나"가 지수적으로 반영한다는 점에 있습니다. 지수함수는 값이 클수록 훨씬 더 크게 반영된다는 성질이 있기 때문에, 내적값이 클수록 유사도가 높다는 S의 성질에 지수적인 증폭을 더해서 강한 대비(contrast)를 만든다는 목적을 극대화할 수 있습니다.

**forward**

```python
# Before — 7단계(attention_score.py)
def forward(self, X: np.ndarray) -> NumpyValue:
    X_val = NumpyValue(X)
    Q = X_val @ self.Wq
    K = X_val @ self.Wk
    S = Q @ K.transpose()
    return S

# After — 8단계(scaled_dot_product_attention.py)
def forward(self, X: np.ndarray) -> tuple:
    X_val = NumpyValue(X)
    Q = X_val @ self.Wq
    K = X_val @ self.Wk
    V = X_val @ self.Wv

    S = Q @ K.transpose()
    S_scaled = S * (1.0 / np.sqrt(self.d_k))
    A = S_scaled.softmax(axis=-1)
    O = A @ V

    return O, A
```

- 7단계는 `Q`, `K`만 있었고, `S`를 반환한 뒤 forward가 끝났습니다.
- 8단계는 `V = X_val @ self.Wv`가 새로 추가됩니다. `Wq`, `Wk`와 마찬가지로 같은 `X_val`에서 시작하지만 별도의 가중치를 거친 세 번째 갈래입니다.
- `S_scaled = S * (1.0 / np.sqrt(self.d_k))`가 scaling입니다. `d_k`(query/key의 차원)가 커질수록 내적값의 분산이 커져서, softmax가 특정 위치에만 쏠리는(saturate) 문제를 완화합니다.
- `A = S_scaled.softmax(axis=-1)`이 7단계에는 없던 정규화 단계입니다. `S`는 임의의 실수였지만, `A`는 각 행의 합이 정확히 1인 확률 분포처럼 바뀝니다.
- `O = A @ V`가 정보 이동이 실제로 일어나는 지점입니다. `A[i,j]`(비중)만큼 `V[j]`(정보)를 섞어서, `O[i]`가 "다른 위치들의 정보를 관련도에 비례해서 조합한 값"이 됩니다.
- forward 실행 시, NumpyValue 동작 과정
  1. (`X_val @ self.Wv`) 7단계의 `Q`, `K`와 동일한 방식으로 `V`가 생성됩니다. `X_val`이 `Q`, `K`, `V` 세 갈래에 동시에 자식으로 기록됩니다.
  2. (`Q @ K.transpose()`, `* (1.0/sqrt(d_k))`) 7단계와 동일한 방식으로 `S`가 계산된 뒤, 스칼라 곱셈(`__mul__`, 4단계에서 이미 구현된 연산)으로 스케일이 조정됩니다.
  3. (`.softmax(axis=-1)`) 새로 추가된 연산입니다. 각 행(row)에서 최댓값을 뺀 뒤(`overflow` 방지) 지수함수를 취하고, 그 행의 합으로 나눕니다. `_backward`는 "같은 행 안의 모든 원소가 서로 영향을 주는" 방식(`y_i * (dL/dy_i - sum_j(dL/dy_j * y_j))`)으로 정의만 해둡니다.
  4. (`A @ V`) 곱셈 연산이 실행되어 최종 출력 `O`가 만들어집니다. `_prev`에는 `A`, `V`가 자식으로 기록됩니다.
  5. `(O, A)`를 반환합니다. `A`를 함께 반환하는 이유는, 각 위치가 다른 위치를 얼마나 참조했는지 직접 확인하기 위함입니다.

## 결과 정리

**표 1. scaled dot-product attention 검증 결과**
| 검증 항목 | 결과 |
|---|---|
| softmax 정규화 (각 행 합) | 1.0 (전부 정확히 일치) |
| 전체 forward-backward vs 수치 미분 | `Wq` 6개 원소 전부 일치 |
| `O`가 `A @ V`(가중합) 정의와 일치하는가 | 정확히 일치 |
| attention weight가 균등 분포인가 | 아니오 — `Wq`, `Wk`가 서로 다르므로 위치마다 다른 비중으로 정보를 섞음 |

**표 2. scaling 유무에 따른 softmax 쏠림 현상 (d_k별 최댓값 비중)**
| `d_k` | scaling 없음 | scaling 적용 |
|---|---|---|
| 4 | 0.4290 | 0.3099 |
| 64 | 0.9968 | 0.5092 |
| 512 | 1.0000 | 0.5127 |

## 결론 및 한계

- 7단계에서 "유사도 점수만 있고 정보 이동이 없다"고 짚었던 한계가 해결됐습니다. `O`가 `A @ V`의 정의와 정확히 일치한다는 게 검증됐고(표 1), attention weight `A`가 균등 분포가 아니라는 것도 확인되어, `Wq`, `Wk`, `Wv`가 각자 다른 역할을 하는 별도의 가중치로 실제로 작동하고 있다는 근거가 됩니다. (균등하면 어느 위치에 더 관련있는지 구분하지 못하고 똑같이 취급하는 셈)
- scaling(`1/sqrt(d_k)`)의 필요성도 실측으로 확인됐습니다(표 2). `d_k=512`(Transformer 논문의 전형적인 차원 수)에서 scaling 없이는 softmax의 최댓값 비중이 사실상 `1.0`까지 치솟아, 한 위치만 참조하고 나머지는 완전히 무시하는 극단적인 상태가 됩니다. scaling을 적용하면 `d_k`가 커져도 비중이 `0.5` 근처로 안정적으로 유지됩니다.
- 다만 지금 구현은 attention head가 1개뿐입니다. `Wq`, `Wk`, `Wv` 한 세트만으로는, "한 가지 관점"에서의 관련도만 포착할 수 있습니다. 문장 안에서 문법적 관계(예: 주어-동사)와 의미적 관계(예: 대명사-선행사)는 서로 다른 종류의 관련성인데, 하나의 `Wq`/`Wk` 세트로는 이 다양한 관계를 동시에 표현하기 어렵습니다.
- 이 한계가 9단계(multi-head attention)로 넘어가는 이유입니다. 9단계는 지금의 `Wq`, `Wk`, `Wv` 세트를 여러 개(head) 병렬로 두고, 각 head가 서로 다른 관점의 관련성을 포착하도록 한 뒤 그 결과를 합칩니다.
